# Правила работы в Flow / I&I Studio

Перед изменениями интерфейса прочитай style-guide.md, особенно раздел 8 «Обязательный контракт», и CSS затронутого экрана. Это обязательные правила проекта для новых страниц, компонентов и правок.

- Переиспользуй существующие компоненты, классы и тематические токены. Источники: resources/css/base.css, buttons.css, dark-theme.css и form-fields.css.
- Следуй таблицам типов кнопок, hover, размеров и цветов в style-guide.md. Сохраняй минималистичный стиль Flow, светлую/тёмную темы и мобильную адаптивность.
- У текстовых input и textarea hover запрещён, включая hover от обёртки. Select сохраняет hover. Видимый фокус остаётся.
- Не добавляй lift/translateY/scale кнопкам. Hover — только для устройств с hover и точным указателем; disabled не реагирует на hover.
- Все модалки открываются одинаково: фон 200ms, карточка 240ms с лёгким scale/opacity. Закрываются сразу, без анимации. Уважай prefers-reduced-motion и используй общие keyframes из header.css.
- Не меняй соседние экраны и существующие размеры за пределами задачи. Для нового варианта предпочитай общий компонент вместо локального дублирования CSS.
- Проверка backend или сборка не доказывает качество frontend. При разрешённых UI-проверках осмотри затронутый интерфейс в обеих темах и на мобильном экране. Отдельно сообщи о непроверенном визуальном поведении.
- Прямые инструкции пользователя имеют приоритет, включая запрет тестов, сборок или браузерных проверок.
- Коммить и пушь завершённые изменения, если пользователь не просил оставить их локально. Добавляй только явные файлы задачи, сохраняй чужие изменения.
- На телефонах (до 640px) все текущие и будущие модалки полноэкранные: 100% × 100dvh, без внешних отступов и скруглений; учитывать safe-area и внутреннюю прокрутку. Hover в CSS/React не активируется от касания; видимый клавиатурный фокус сохраняется.
