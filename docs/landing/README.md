# Структура следующей версии лендинга I&I Studio

Это готовое предложение структуры и контента по предоставленной переписке, а не подключённое обновление интерфейса. Русский — рабочий язык согласования; сайт сохраняет EN / UK / RO. Ссылки на конструкторы из переписки не использовались как шаблоны.

- `landing.ru.json` — порядок блоков, тексты, услуги, CTA, FAQ и правила публикации.
- `briefs.ru.json` — короткая первичная заявка и спецификация последующих брифов. `questions` описывают вопросы для проектирования формы, а не исполняемую схему полей.

## Почему такая структура

Первый экран → выбор услуги → принципы работы → этапы → стоимость → FAQ → короткая заявка. Для новой студии доверие строится на понятном составе работ и условиях, а не на придуманных цифрах. Кейсы и отзывы добавляются по мере появления подтверждённых материалов. Существующие учебные работы допустимы только с явной пометкой.

Длинные анкеты со скриншотов перенесены на второй этап. На первом контакте человек не обязан знать CPA, настройки аналитики и рекламных кабинетов. Для неизвестных ответов предусмотрена помощь. По дополнительно переданным `fb-ads-form-spec.md`, `tiktok-ads-form-spec.md` и `google_ads_form.json` уточнена спецификация; TikTok добавлен в `planned_briefs` с отдельными вопросами о стране бизнеса, видео, UGC и использовании опубликованных роликов. Его публикация зависит от готовности команды вести эту услугу.

Предложения из исходных файлов адаптированы: нет автоматического перехода к оплате, обязательной ссылки для бизнеса без сайта, загрузок до 1 ГБ и обещания «запуск возможен» для любой ограниченной категории. Условия площадок специалист проверяет перед оценкой проекта. Это проектирование структуры по материалам маркетолога, а не проверка актуальных рекламных правил.

## Подключение к текущему Flow

Сейчас главная отображается через `resources/js/legacy/HomeMarkup.jsx`; тексты находятся в `resources/js/content/translations/`. Google Ads и Meta Ads уже имеют отдельные компоненты `GoogleAdsBrief.jsx` и `MetaAdsBrief.jsx`. Их следует доработать, а не создавать параллельные формы.

| ID в предложении | Текущий service_type | Интеграция |
| --- | --- | --- |
| website | landing / corporate / redesign | Уточнить тип сайта перед передачей в существующую форму |
| google_ads | ads | Сохранить текущий контракт Google Ads |
| meta_ads | meta-ads | Сохранить brief_data и текущую серверную валидацию |
| marketplaces | пока отсутствует | Для отдельной услуги добавить контракт, валидацию, кабинет и админку; до этого обсуждать через other |
| advice | consultation | Использовать существующий сценарий консультации |

ID из JSON нельзя напрямую отправлять в текущий `POST /inquiry`: контроллер принимает свой набор `service_type` и поля. Короткая форма также потребует адаптера или отдельного обработчика; не выдавать её за уже рабочую.

При подключении CTA переносит выбранную услугу в форму и ставит фокус на заголовок. Для короткой заявки достаточно встроенного блока. Подробный бриф использует существующие компоненты и стили. Сохранить тематические токены, клавиатурный фокус, отсутствие hover у текстовых полей и полноэкранные содержательные модалки до 640px.

До публикации: согласовать услуги и обязанности, перевести тексты на EN / UK / RO (UK соответствует URL `/ua`), указать действующую политику конфиденциальности, подключить реальное сохранение и состояния ошибок. Цены и сроки `null` означают «после оценки», не нулевую цену. Автоплатежи, письма, напоминания и восстановление по email не входят в эту спецификацию как готовые функции.

Тесты, сборка и браузерные проверки не запускались по просьбе пользователя. Интерфейс и обработчики в этой задаче не менялись.
